# 决策卡：业务逻辑 / 支付 / 竞态

## 何时用
- 支付、优惠券、积分、余额、库存、抢购。
- 验证码、短信、邀请、投票、点赞。
- 有状态变更、可重复提交、并发窗口。

## 首打 5 步
1. 画业务流：下单 → 支付 → 回调 → 发货/退款，找可篡改的字段。
2. 价格/数量/优惠券：改价、改数量、券挂到别人商品、重复用券。
3. 并发：双花、超卖、重复领取、验证码并发；只用少量请求（HTTP/2 单包）。
4. 验证码/短信：枚举、万能码、限频绕过；不要短信轰炸。
5. 证明到“一次操作造成一次非预期资产变化”即停。

## 判定
- 价格/数量被篡改且订单成立。
- 同一资源被重复消费/重复到账。
- 库存超卖、券超领、积分负数。
- 证据含时间戳、请求、回包、前后余额变化。

## 硬红线
- 不做真实资损；不批量；不轰炸短信。
- 不改/删别人已有的券、订单、余额。
- 验证成功立即停止，不复现第二次。

## 常见坑
- 只看前端价格，没看服务端校验。
- 并发量太大，变成压测。
- 把“能重复提交”直接当高危，没证明资产变化。
- 券绑定测试动到别人的商品/账户。
